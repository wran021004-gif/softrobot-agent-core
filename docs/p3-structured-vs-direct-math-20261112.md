This is a P3 passive numerical API interface, not a claim to expose every active-control API used by other tasks.

Optional `source_record_indices` selects exact records, including multiple records from a prior multi-evaluation result; it is not an arbitrary JSON pointer or external data source.

The adapter selects inputs, passes parameters and returns existing numerical outputs; it does not reimplement a mathematical engine.

Explicit dynamic profiles use the existing scope/fidelity binding; explicit tendon-limit interventions use owned tendon names and the existing paired executor. Unsupported observable/mode combinations, discrete derivative targets, invalid paths/bounds, incompatible sources, missing scalars, active-set switches and invalid comparisons remain unavailable or diagnostic. `not_defined`/`not_comparable` is never changed to zero or a certified direction. Interaction remains a finite four-point contrast, not a strict mixed derivative.

## Scope of the C2 comparison

The treatment is semantic question construction and operation composition versus explicit bound numerical API calls. Both retain registered parameters/observables, frozen physics, numerical applicability, validity checks and ordinary physical search. Direct intentionally lacks automatic question/Plan synthesis, candidate-direction handoffs and semantic operation scheduling; Main performs that organization. It has no arbitrary formula construction or active-controller functionality because those are not available P3 mathematical capabilities.

Physical model evaluations and their validity checks share implementations; arithmetic and solver APIs are the same ones used underneath the structured layer. Host invocation boundaries, reuse choices and operation/model-evaluation charges remain observable. A single future paired run is exploratory and cannot establish a stable quantitative C2 contribution; record Provider/public operations, mathematical reservations, actual model calls, reused records and separately attributed episodes/steps.
